# Наборы признаков (feature sets) в ноутбуке `14_model_comparison_multi_calc_resist_warnings`

Документ описывает **шесть** вариантов входных колонок для табличных моделей (tabular models) в ноутбуке [`notebooks/14_model_comparison_multi_calc_resist_warnings.ipynb`](../notebooks/14_model_comparison_multi_calc_resist_warnings.ipynb). Это те же наборы, что и в логике [`13_model_comparison_multi_calc_resist.ipynb`](../notebooks/13_model_comparison_multi_calc_resist.ipynb): сравнивается качество прогноза при разном составе признаков (features).

---

**A:** Минимальный набор «когда и какая операция». Входят код операции (`op_code`), номер месяца и год строки (`month`, `year`) — то есть календарная метка (calendar label) прогнозируемого месяца, и число рабочих дней в этом месяце из поля `workDayMonth_2` (оно же приходит из параметров расчёта (calculate parameters), развёрнутых в колонку). Нет минут расчёта (`calculate_minute`), нет прошлых значений параметров `calculate_parameter` в виде лагов (lags) `calc_*_lagN`, нет прошлых значений фактического объёма (`fact_value`).

**B:** Расширенный набор: к базе из набора **A** добавлены **минуты**, за которые выполнялся расчёт строки (`calculate_minute`), и для **каждого** числового ключа `calc_*`, который есть в данных после подготовки, — отдельные столбцы со значениями этого параметра **не за текущий месяц**, а за **1, 2, 3, 4, 5, 6 и 12 месяцев раньше** по тому же ряду операции (`operation_id`). Имена вида `calc_<имя>_lag1` … `lag6` и `lag12`. Смысл: модель видит «как нагрузка и правила расчёта выглядели в недавнем прошлом», не подставляя сырые `calc_*` текущего месяца (их в наборе после преобразования нет — скалярные `calc_*` удаляются, остаются только лаги (lags)).

**C:** Как **B** по базе (код, дата, рабочие дни, минуты расчёта), но лаги (lags) по `calculate_parameter` строятся **не для всех** ключей, а только для **семи** из списка разрешённых (`CALC_WHITELIST`): рабочие дни в месяце (`calc_workDayMonth_2`), часы в неделе (`calc_hourInWeek_12`), число рабочих часов (`calc_numberWorkHour_1`), показатель эффективности (`calc_effective_13`), отсутствия (`calc_absenteeism_14`), факт занятости (`calc_employFact_7`) и отдельный показатель по «сопротивлению» (`calc_resist_10`) — вместо пар параметров про переработки и перекрёстные операции (`calc_overtime_4`, `calc_cross_5`), которые входят в полный набор **B**. То есть **C** — более узкий и осмысленно отобранный набор прошлых расчётных величин.

**A+lags:** Всё из **A**, плюс три признака по **прошлому фактическому числу операций** (или тому, что лежит в `fact_value`) в разрезе той же операции: значение за предыдущий месяц (`lag_1`), за тот же календарный месяц год назад (`lag_12`), и сглаженная величина — среднее (rolling mean) по трём завершённым месяцам перед текущим (`rolling_mean_3`, в коде считается после сдвига на один месяц (shift), чтобы не подмешивать текущий факт).

**B+lags:** Всё из **B**, плюс те же три признака по факту (`lag_1`, `lag_12`, `rolling_mean_3`), что и в **A+lags**.

**C+lags:** Всё из **C**, плюс те же три признака по факту, что и в **A+lags** и **B+lags**.

---

## Кратко: чем наборы отличаются

| Набор (feature set) | `calculate_minute` | Лаги (lags) по параметрам расчёта `calc_*` | Лаги (lags) по факту `fact_value` |
|---------------------|-------------------|---------------------------------------------|-----------------------------------|
| **A** | нет | нет | нет |
| **B** | да | да, **все** доступные `calc_*` (1–6 и 12 месяцев) | нет |
| **C** | да | да, только **7** ключей из `CALC_WHITELIST` | нет |
| **A+lags** | нет | нет | да (`lag_1`, `lag_12`, `rolling_mean_3`) |
| **B+lags** | да | как в **B** | да |
| **C+lags** | да | как в **C** | да |

Константы `LAG_FEATURES`, `CALC_WHITELIST` и сборка `FEATURE_SETS` задаются в ноутбуке **14**; сдвиги по месяцам для `calc_*` реализованы в [`scripts/calc_lag_features.py`](../scripts/calc_lag_features.py) (`add_calc_shift_lags`, `DEFAULT_CALC_SHIFTS`).
